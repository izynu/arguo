# Research planning

Planning happens before searching. A plan written after the search is a
justification, not a plan. This file covers how to turn a question into an
inspectable plan with explicit stopping rules.

## What the plan must contain

- Research question, restated in one sentence in plain language.
- Claim type the answer requires: fact, comparison, causal explanation,
  definition, current state, or forecast.
- Scope fixes: jurisdiction, population, geography, units, currency.
- Time boundary: the date range the question is about, which is not the same
  as the date range you search.
- Subquestions with priorities and preferred source types.
- Anticipated limitations you can already predict.
- Stopping rules and budget.

## Decomposition rules

- Produce 3 to 7 subquestions. Fewer than 3 usually means the question has not
  been understood; more than 7 means you are writing a book, not a report.
- Each subquestion must be answerable by evidence: documents, data, records.
  "Is this policy good" is not answerable; "what measurable outcomes followed
  this policy in comparable jurisdictions" is.
- Write an evidence requirement for each subquestion: what would count as an
  answer, and what would count as insufficient. This is what you will compare
  against at the end.
- Assign priorities 1 to 3. Priority 1 subquestions must be answered or
  explicitly reported as unresolved before delivery.

## Time boundaries

- Distinguish the question's time boundary ("what happened between 2015 and
  2020") from the search recency need (recent methods matter even for old
  questions).
- If the requester states no boundary, choose one, record it, and say why.
- For questions about the present state, record the as-of date of the report.

## Depth profiles

- Quick: one or two subquestions, priority 1 only, a handful of sources,
  suitable for a single verifiable fact.
- Standard: full decomposition, primary sources for load-bearing claims,
  contradiction pass included.
- Deep: adds systematic search logging, source assessments for every load
  bearing source, and an explicit corroboration map.

State which profile you are using. Do not silently downgrade to quick because
the first search result looked good.

## Stopping rules

Write at least one of these before searching, then obey it:

- Saturation: two consecutive search rounds produce no new load-bearing
  evidence, only restatements of what the ledger already holds.
- Budget: a fixed number of search rounds or a time limit is reached.
- Verdict reached: the evidence requirements for all priority 1 subquestions
  are met, or their insufficiency is established.
- Safety: the question moves into territory covered by privacy and safety
  rules, and the scope must be narrowed or refused.

## Budget guidance

- Track queries issued, sources retrieved, and ledger rows written. These three
  numbers make the budget real instead of a feeling.
- When the budget is exhausted, deliver the report with whatever verdict the
  evidence supports, including insufficient evidence. Do not extend the budget
  invisibly.

## Pre-search checklist

- [ ] Question restated in one sentence.
- [ ] Claim type identified.
- [ ] Scope, jurisdiction, units, and time boundary fixed and recorded.
- [ ] 3 to 7 subquestions written, each with an evidence requirement.
- [ ] Stopping rule and budget written.
- [ ] Assumptions and ambiguities recorded.

Fill templates/research-plan-template.md with these fields. A plan that is not
written down cannot be audited.
